# Тестовые сценарии

Сценарии лежат в `tests/scenarios/*.json`, документы для них — в `tests/scenarios/docs/`.
Каждый сценарий описывает вход (документ, рейтинги, уровни, переменные окружения) и ожидаемый результат.

Запуск всех сценариев с таблицей «пройден / не пройден»:

```bash
python scripts/run_scenarios.py          # все сценарии
python scripts/run_scenarios.py 03 06    # только выбранные
```

Сценарии выполняются на провайдере `mock` с отключённым OpenAlex, поэтому результат детерминирован.
Те же сценарии запускаются в `pytest` (`tests/test_scenarios.py`).

## Формат сценария

```json
{
  "name": "Только один рейтинг",
  "description": "Выбран только рейтинг THE ...",
  "input": "data/samples/univ_b.pdf",
  "rankings": ["THE"],
  "levels": ["faculty", "department", "teacher"],
  "env": {"LLM_PROVIDER": "anthropic"},
  "expected": {"status": "completed", "indicator_rankings": ["THE"]}
}
```

`levels` и `env` необязательны. Поддерживаемые проверки в `expected`:

| Ключ | Что проверяется |
|---|---|
| `status` | итоговый статус: `completed` / `partial` / `failed` (обязательный) |
| `revisions` | число циклов доработки |
| `message_contains` | подстрока в сообщении для пользователя |
| `min_goals` | минимальное число извлечённых стратегических целей |
| `min_goal_coverage` | минимальная доля целей, покрытых KPI (0..1) |
| `indicator_rankings` | рейтинги, к которым относятся индикаторы |
| `kpi_levels` | уровни каскада, на которых есть KPI |
| `mission_startswith` | начало текста миссии |
| `issue_category` | у проверяющего есть замечание этой категории |

## Сценарии

| № | Сценарий | Вход | Ожидаемый результат | Что демонстрирует |
|---|---|---|---|---|
| 01 | Исследовательский университет | `univ_a.pdf`, QS + THE | `completed`, 1 доработка, ≥5 целей, покрытие целей 100% | цикл проверки: первая версия KPI перекошена в сторону публикаций, Reviewer возвращает её, вторая версия одобрена |
| 02 | Технический университет | `univ_b.pdf`, QS + THE | `completed`, 0 доработок, покрытие целей 100% | другой профиль вуза, одобрение с первой итерации |
| 03 | Только один рейтинг | `univ_b.pdf`, THE | `completed`, индикаторы только THE | фильтрация индикаторов и связей по выбранным рейтингам |
| 04 | Неполный каскад | `univ_a.md`, QS, уровни факультет → кафедра → преподаватель | `completed`, KPI только на этих уровнях | верхний уровень каскада меняется, у KPI факультета нет родителя |
| 05 | Стратегия без явной миссии | `univ_b_no_mission.md` | `completed`, миссия начинается с «(не сформулирована явно)» | агент восстанавливает миссию и честно помечает это |
| 06 | Противоречащие цели | `univ_a_conflict.md` (G2 «меньше студентов на преподавателя» против G6 «+40% приёма без роста штата») | `partial`, замечание «противоречие целей» | система не скрывает противоречие: Reviewer не одобряет, после доработок срабатывает защита от зацикливания, пользователь получает последнюю версию и объяснение |
| 07 | Повреждённый файл | `broken.pdf` | `failed`, «файл повреждён» | ошибка инструмента `pdf_reader` превращается в понятное сообщение |
| 08 | Очень короткий документ | `short.md` (одна цель) | `failed`, «нужно не менее 3» | критерий завершения MissionAnalyst и лимит доработок ответа LLM (2) |
| 09 | Пустой документ | `empty.txt` | `failed`, «пуст» | проверка входа до вызова LLM |
| 10 | LLM недоступен | провайдер `anthropic` без ключа | `failed`, «ANTHROPIC_API_KEY» | понятное сообщение об ошибке настройки, без падения |

Результат текущей версии: **10 из 10 (100%)**.

## Дополнительные тесты на сбои (`tests/test_failures.py`)

Сбои, которые сложно задать файлом сценария, проверяются в pytest подменой провайдера LLM:

| Тест | Ситуация | Ожидание |
|---|---|---|
| `test_llm_unavailable` | LLM не отвечает (ConnectionError) | 3 попытки с паузами, затем `failed` с сообщением «не ответил после 3 попыток»; повторы видны в логе |
| `test_invalid_json_is_retried` | первый ответ каждого агента — не JSON | повторный запрос с текстом ошибки, задача `completed` |
| `test_invalid_json_gives_up_after_two_fixes` | KPIDesigner всегда отвечает неверной структурой | ровно 3 вызова LLM (запрос + 2 доработки), затем понятная ошибка |
| `test_invalid_plan_falls_back_to_default` | LLM вернул план с нарушенным порядком агентов | используется стандартный план |
| `test_revision_limit` | Reviewer никогда не одобряет, `MAX_REVISIONS=1` | `partial`, «MAX_REVISIONS=1», возвращена последняя версия KPI |
| `test_loop_detection` | после доработки KPI не изменились | `partial`, «зацикливание» |
| `test_timeout` | `TASK_TIMEOUT_SEC=0` | `partial`, «TASK_TIMEOUT_SEC» |
| `test_unexpected_orchestrator_error_is_caught` | непредвиденное исключение внутри оркестратора | `failed` с текстом ошибки, без трейсбека |
| `test_broken_pdf`, `test_empty_document`, `test_unsupported_format` | плохие входные файлы | `failed` с понятным сообщением |
| `tests/test_openalex.py` | OpenAlex доступен / в кэше / недоступен / отключён | расчёт ориентиров, работа из кэша без сети, при недоступности — `available: false` без падения |
